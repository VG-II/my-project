# Голосовой ввод + скриншоты в буфер

**Когда брать:** в самом начале работы, до того как начнёшь много писать промпты.
**Что делает:** ускоряет тебя в 3-5 раз. Голосом диктуешь быстрее, скриншоты показывают Qwen контекст вместо 1000 слов.
**Результат:** работает голосовой ввод по горячей клавише + скриншот сразу в буфер обмена.

## Часть 1. Голосовой ввод

Wispr Flow (лучшее на рынке, платный) - [wisprflow.ai](https://wisprflow.ai). Есть пробный период.
Super Whisper (Mac) - [superwhisper.com](https://superwhisper.com).
Бесплатный fallback: Mac - System Settings → Keyboard → Dictation. Windows - `Win + H`.

### Промпт

```prompt
Помоги мне установить Wispr Flow (или Super Whisper, если я скажу) на [Mac/Windows].

1. Дай прямую ссылку на скачивание.
2. Объясни простыми словами, что сделать после скачивания: куда перетащить, какие разрешения дать (микрофон, accessibility).
3. Помоги настроить горячую клавишу: одно нажатие - начал диктовать, отпустил - текст вставился в активное окно.
4. Продиктуй короткий чек-лист как проверить что всё работает.

Действуй по одному шагу. Жди моих ответов.
```

**Проверка:** открой любой текстовый редактор, нажми горячую клавишу, скажи «привет, проверка связи» - должен появиться текст.

## Часть 2. Скриншот в буфер обмена

Скриншот должен **сразу** попадать в буфер (не на рабочий стол). Дальше `Ctrl/Cmd + V` в чат с Qwen.

### 🍎 Mac

`Cmd + Shift + Ctrl + 4` - скриншот области в буфер.

Если неудобно - переназначь:
1. System Settings → Keyboard → Keyboard Shortcuts → Screenshots
2. «Copy picture of selected area to the clipboard»
3. Кликни и нажми свою комбинацию

### 🪟 Windows

`Win + Shift + S` - Snipping Tool. Выделил - в буфере.

**Проверка:** сделай скриншот → открой Qwen Code → `Ctrl/Cmd + V` → должен появиться в чате.


# Звуковые хуки (hooks)

**Когда брать:** сразу после онбординга, до начала реальной работы.
**Что делает:** включает звуковое уведомление когда Qwen закончил задачу или ждёт твоего разрешения. Ты не пропустишь момент когда можно продолжать.
**Результат:** `.qwen/settings.json` с двумя hooks (Stop + Notification).

## Проблема которую решает

Ты запустил задачу, ушёл за чаем. Qwen закончил через 2 минуты и ждёт твоего ответа. Ты думаешь что он ещё работает. Полчаса потеряно.

## Промпт

```prompt
Настрой мне в .qwen/settings.json звуковые уведомления (hooks):

1. Звук при завершении задачи (Stop hook) - чтобы я слышал, когда ты закончил работу.
2. Звук при запросе разрешения (Notification hook) - чтобы я слышал, когда ты ждёшь моего «да/нет».

Используй системный звук моей операционной системы.

За образцом структуры посмотри templates/qwen-settings.json.example в этом проекте - там пример hooks для Mac/Windows с fallback.

Перед изменением файла - покажи мне текущее содержимое .qwen/settings.json. После изменения - покажи итоговый файл и объясни, что добавил.
```

## Проверка

Задай любую микрозадачу («посчитай 2+2 и всё»). Когда Qwen закончит - должен пикнуть.

Если не пикает:
- Проверь что звук не отключён в системе
- Проверь что `.qwen/settings.json` содержит секцию `hooks`
- Перезапусти VS Code


# 4 запрета безопасности

**Когда брать:** сразу после `02-hooks.md`, обязательно перед включением YOLO mode.
**Что делает:** блокирует 4 опасных типа команд на уровне `.qwen/settings.json`. Даже если ты случайно скажешь «удали всё» - Qwen остановится и переспросит.
**Результат:** `.qwen/settings.json` с секцией `permissions.deny`.

## Что именно запрещаем

| Команда | Почему опасно |
|---|---|
| `rm -rf` и массовое удаление | Можно случайно стереть диск |
| `curl` + `export` переменных | Утечка секретов наружу |
| Чтение `.env` целиком | API-ключи и пароли попадают в транскрипт |
| `wget` с подставленными переменными | Экспорт данных наружу |

## Промпт

```prompt
Настрой мне в .qwen/settings.json правила безопасности. ЗАПРЕТИ:

1. Команды вида `rm -rf` и любое массовое удаление файлов или папок без явного подтверждения от меня.
2. Связку `export` + `curl` - любую отправку переменных окружения наружу через curl.
3. Чтение файлов .env и любых файлов с секретами, ключами, паролями (читать .env можно только через grep по конкретной переменной).
4. `wget` с подставленными переменными - любую отправку моих данных наружу через wget.

Используй секцию permissions.deny (или эквивалентную секцию в актуальной версии Qwen Code). За образцом посмотри templates/qwen-settings.json.example - там есть пример секции permissions.deny с 9 правилами (4 базовых + расширения).

Перед изменением - покажи текущий файл. После изменения - покажи итоговый .qwen/settings.json и объясни каждое правило одной строкой.
```

## Проверка

Попроси Qwen выполнить `rm -rf tmp/` в тестовой папке - он должен остановиться и попросить явное подтверждение.

Попроси прочитать `.env` - он должен отказаться или использовать `grep`.


# Интервью и заполнение `.business/`

**Когда брать:** только если AUTOPILOT не сработал. В нормальном потоке интервью проводится автоматически на шаге 8 онбординга.
**Что делает:** Qwen задаёт тебе серию вопросов про проект и сам пишет файлы в `.business/`.
**Результат:** заполненная папка `.business/` с 7 подпапками (company, products, audience, goals, economics, marketing, assets).

## Промпт

```prompt
Ты помогаешь мне создать папку .business/ для моего проекта по методологии «второго мозга». Это скрытая папка с бизнес-контекстом, которую ты потом будешь читать перед каждой задачей, связанной с бизнесом.

МОЯ ИДЕЯ В ОДНОМ ПРЕДЛОЖЕНИИ:
[ВПИШИ СЮДА СВОЮ ИДЕЮ]

ТИП ПРОЕКТА: [коммерческий / некоммерческий]

ДЕЙСТВУЙ ПО ШАГАМ:

ШАГ 1. Создай в корне проекта папку .business/ (если её нет) и подпапки:
company/, products/, audience/, goals/, economics/, marketing/, assets/.
Создай INDEX.md в корне .business/ с заголовком «Бизнес-контекст проекта» и пустым оглавлением (заполнишь в конце).
Убедись что .business/ в .gitignore (если нет - добавь).

ШАГ 2. Возьми у меня интервью по семи блокам в таком порядке:
company → products → audience → goals → economics → marketing → assets.

ПРАВИЛА ИНТЕРВЬЮ:
- Иди ПО ОДНОМУ блоку за раз. Закончил блок - записал файлы - перешёл к следующему.
- В каждом блоке задавай вопросы ПО ОДНОМУ.
- К КАЖДОМУ вопросу сразу предлагай 3-4 варианта ответа на основе моей идеи. Я выберу номер, скажу «свой вариант: ...», или «не знаю».
- Если я говорю «не знаю» - предложи свой вариант, спроси «согласен?».
- Если короткий ответ - 1-2 уточняющих вопроса с вариантами.
- Не больше 4-5 вопросов на блок.
- Для типа «некоммерческий» пропусти или упрости блоки audience/objections, economics/unit-economics, marketing/funnel.

ШАГ 3. После каждого блока СРАЗУ записывай результат в соответствующие файлы:
- company: about, team, values, legal
- products: overview, pricing
- audience: avatar, segments, objections, journey
- goals: annual, quarterly, monthly, kpi
- economics: unit-economics, revenue, costs, forecast
- marketing: channels, funnel, competitors, content
- assets: brand-guidelines, testimonials

Если в блоке мало данных - создай файл с заголовком и пометкой «заполнить позже», не пропускай.

ШАГ 4. После ВСЕХ блоков обнови INDEX.md:
- название проекта одной строкой
- одно предложение «о чём проект»
- список всех файлов со строкой описания каждого
- правило: «при работе читай только нужный файл, не загружай всё сразу»

ШАГ 5. После блока products (блок 2) сделай краткий Reality Check идеи - назови 2-3 конкретных риска которые ты видишь в моей идее в одном абзаце. Затем спроси: хочешь обдумать риски или продолжаем интервью?

ШАГ 6. В конце покажи дерево созданной .business/ и спроси что добавить или изменить.

ВАЖНО:
- Всегда отвечай на [русском / английском - выбери].
- Не пиши код, только файлы и интервью.
- Не задавай все вопросы сразу - только по одному.

Начинай с ШАГА 1, потом ШАГ 2 блок company.
```

## Советы

- **Отвечай вдумчиво.** Чем детальнее ответ - тем умнее Qwen в дальнейшей работе.
- **Один блок = ~5-10 минут.** Суммарно 50-70 минут. Можно делать в несколько сессий.
- **Если Qwen ушёл в сторону** - скажи «вернись к блоку X» и он продолжит.


# Генерация QWEN.md под твой проект

**Когда брать:** после заполнения `.business/` через интервью.
**Что делает:** создаёт `QWEN.md` в корне проекта - главный файл с правилами работы, который Qwen читает первым перед каждым действием.
**Результат:** `QWEN.md` под твой стек и тип проекта, не больше 200 строк.

## Зачем

`.business/` - это **знания** (зачем делаем проект). `QWEN.md` - это **правила** (как Qwen работает со знаниями). Без `QWEN.md` Qwen каждый раз «придумывает» подход заново. С ним - следует единому методу.

⚠️ **Не больше 200 строк** - иначе сжигаешь токены каждый запрос.

## Промпт

```prompt
Создай в корне проекта файл QWEN.md. Основа - шаблон в templates/QWEN.md.tmpl.

Действуй так:

1. Прочитай templates/QWEN.md.tmpl - это заготовка с плейсхолдерами.
2. Прочитай .business/INDEX.md и все файлы внутри .business/ - чтобы понять мой проект.
3. Заполни все плейсхолдеры в шаблоне ({{PROJECT_NAME}}, {{PROJECT_ONE_LINER}}, {{STACK}}, {{LANGUAGE_RULE}}) на основе моих ответов из .business/.
4. Если каких-то данных не хватает - задай мне уточняющие вопросы ПО ОДНОМУ с 3-4 вариантами ответа.
5. Запиши итоговый файл в корень проекта как QWEN.md.
6. Проверь что файл не больше 200 строк. Если больше - сократи, убирая воду. НЕ удаляй разделы про план для каждой функции и про рефлексию.
7. Покажи мне итоговый файл и спроси что доработать.

Важно: два правила должны остаться в QWEN.md обязательно:
- «План для каждой новой функции в plans/»
- «Ретроспектива в конце каждой сессии в retrospectives/»

Всегда отвечай на русском.
```

## Проверка

После создания задай Qwen микрозадачу: «создай файл HELLO.md с приветствием». Qwen должен:
1. Сначала прочитать `QWEN.md` и `.business/INDEX.md`
2. Создать план в `plans/YYYY-MM-DD-hello.md`
3. Выполнить задачу
4. Обновить план - отметить фазу как `[x]`
5. Написать ретро в `retrospectives/`

Если какой-то шаг пропущен - значит `QWEN.md` написан плохо. Попроси Qwen доработать и повтори тест.


# Создать папку `plans/` с правилами

**Когда брать:** если папка `plans/` отсутствует в проекте (например, ты склонировал не шаблон, а чужой репо).
**Что делает:** создаёт папку `plans/` с README и TEMPLATE.
**Результат:** `plans/README.md` + `plans/TEMPLATE.md`.

## Зачем

Папка `plans/` - память между сессиями. Новый чат Qwen не помнит прошлое. План - помнит.

**Один план = одна функция.** Не «весь проект», а «добавить форму оплаты».

## Промпт

```prompt
Создай в корне моего проекта папку plans/. Внутри создай два файла:

### plans/README.md

Коротко опиши (10-15 строк):
1. Что такое папка plans/ - это место для технических планов реализации функций.
2. Правило: один план = одна функция.
3. Формат имени файла: YYYY-MM-DD-название-функции.md
4. Каждый план делится на фазы. У каждой фазы статус [ ] или [x].
5. В конце плана - итоговый блок: реализован целиком или нет, что осталось.
6. Любой агент обязан актуализировать план после каждой сессии.

### plans/TEMPLATE.md

Шаблон файла плана с разделами:
- Цель (одно предложение)
- Контекст (откуда задача, что есть, чего нет)
- Фазы (с чекбоксами)
- Критерии готовности
- Риски
- Открытые вопросы
- Итог (заполняется в конце)

После создания покажи мне дерево корня проекта (QWEN.md, .business/, plans/, retrospectives/), чтобы я убедился что всё на месте.
```


# Тест-цикл - проверить что всё работает

**Когда брать:** после создания `QWEN.md`, `.business/`, `plans/`, `retrospectives/`. До начала реальной работы над проектом.
**Что делает:** даёт Qwen микрозадачу и проверяет, что он следует всем правилам цикла (читает `.business/` → пишет план → выполняет → обновляет план → пишет ретро).
**Результат:** уверенность, что вся машина работает.

## Промпт

```prompt
Тест-задача: создай в корне проекта файл HELLO.md с одной строкой «Привет от [подставь название проекта из .business/INDEX.md]».

Действуй полностью по правилам из QWEN.md:

1. Сначала прочитай QWEN.md и .business/INDEX.md.
2. Создай план в plans/YYYY-MM-DD-hello.md с одной фазой [ ] «Создать HELLO.md».
3. Выполни задачу.
4. Обнови план - отметь фазу как [x], заполни блок «Итог».
5. В конце сессии запиши ретро в retrospectives/YYYY-MM-DD_HH-MM_hello-test.md по формату из TEMPLATE.md.

Если что-то непонятно - спроси.
```

## Проверка

После выполнения вручную проверь:

- ✅ Появился ли `HELLO.md` в корне проекта?
- ✅ Появился ли план в `plans/YYYY-MM-DD-hello.md` со статусом `[x]` и блоком «Итог»?
- ✅ Появился ли файл ретро в `retrospectives/`?

Если что-то не появилось - значит `QWEN.md` написан плохо. Попроси Qwen доработать и повтори тест.

## Важно

Это **учебная микрозадача**. После её прохождения - удали `HELLO.md`, план и ретро теста. Они показали работу системы, дальше работаешь над реальными задачами.


# Установка скиллов с аудитом безопасности

**Когда брать:** после онбординга, когда готов расширить возможности Qwen.
**Что делает:** ставит базовые рекомендованные скиллы + учит тебя проверять любой скилл на безопасность.
**Результат:** `.qwen/skills/` с нужными скиллами.

## Что такое скилл

**Скилл** - это папка с инструкцией, которую Qwen подтягивает сам, когда видит подходящий триггер. Один скилл умеет делать дизайн, другой - парсить PDF, третий - проводить workflow от ресёрча до деплоя.

Два уровня установки:
- **Глобальные:** `~/.qwen/skills/` - доступны во всех проектах.
- **Локальные:** `.qwen/skills/` в корне проекта - только для этого проекта.

🎯 **Правило:** ставь локально, если скилл нужен конкретному проекту. Глобально - только то, чем реально пользуешься везде. Чем меньше скиллов - тем меньше токенов на триггеры.

## ⚠️ Безопасность

Скилл - это **исполняемая инструкция** от автора. Плохой скилл может:
- прочитать твой `.env` с API-ключами
- отправить их на внешний URL через `curl`/`wget`
- удалить файлы
- запустить вредоносный бинарник

**Ручной чек-лист перед установкой любого скилла:**

1. Открой страницу скилла на Smithery или GitHub.
2. Прочитай `README.md` - что делает, зачем, что требует.
3. Открой главный файл (`SKILL.md` или аналог) и пробеги глазами.
4. Поищи опасные паттерны: `curl`, `wget`, доступ к `.env`, отправку данных на внешние URL, `rm -rf`.
5. Посмотри звёзды и автора. Мало звёзд + неизвестный автор = не ставь.
6. Сомневаешься - прогоняй через промпт-аудит ниже.


# Playwright MCP - Qwen управляет браузером

**Когда брать:** когда у тебя уже есть работающий сайт (локально или в сети) и ты хочешь, чтобы Qwen мог его тестировать сам.
**Что делает:** подключает Playwright MCP - Qwen открывает настоящий браузер, тыкает на кнопки, заполняет формы, делает скриншоты, проверяет мобильную вёрстку.
**Результат:** `.mcp.json` или настройки MCP в проекте + работающая автоматизация браузера.

## Зачем

- Сделал лендинг - Qwen сам открывает его, проверяет формы, шлёт скриншоты с ошибками.
- Надо протестировать чужой сайт - Qwen прогоняет сценарий и пишет отчёт.
- Регрессия после правки - автоматический прогон, чтобы убедиться что ничего не сломал.

⚠️ **Совет:** у некоторых Playwright работает нестабильно. Если у тебя полезут странности - не зависай, поставь альтернативу (Chrome DevTools MCP) и иди дальше.

## Установка

```prompt
Установи Playwright MCP в мой текущий проект Qwen Code.

1. Найди официальный пакет (Microsoft Playwright MCP или @modelcontextprotocol/playwright).
2. Проведи аудит безопасности - это браузер с полным доступом, важно понять что он делает.
3. Если безопасно - установи ЛОКАЛЬНО для этого проекта (в .mcp.json или настройки Qwen Code этого проекта, НЕ глобально).
4. После установки покажи как его вызывать, какие команды доступны (navigate, click, screenshot, fill и т.д.).
5. Сделай проверочный прогон: открой google.com, сделай скриншот, покажи мне.
```

## Твой первый автотест

Когда у тебя появится сайт:

```prompt
Используй Playwright MCP. Открой мой локальный сайт по адресу http://localhost:3000.

1. Сделай скриншот первого экрана.
2. Прокрути страницу вниз до конца - скриншот каждого блока.
3. Найди главную форму (кнопка «Купить» / «Оставить заявку»), заполни тестовыми данными (имя: Тест, email: test@example.com), нажми кнопку.
4. Что произошло после отправки? Скриншот результата.
5. Переключи viewport на мобилку (iPhone 14). Повтори прогон.
6. Собери отчёт: что работает, где баги, какие блоки выглядят плохо на мобилке.
```

Qwen пойдёт и всё сделает. Получишь тестовый отчёт со скриншотами - и ни строчки кода сам не написал.

## Важно про токены

Каждый подключённый MCP добавляет ~2000 токенов в контекст **каждого** сообщения. Не подключай десятки MCP «на всякий случай» - держи только те, которыми активно пользуешься.


# Залить код на GitHub

**Когда брать:** когда проект готов к тому, чтобы его можно было посмотреть или задеплоить.
**Что делает:** создаёт приватный репо на GitHub, делает первый коммит, пушит.
**Результат:** твой код в облаке, видишь по ссылке.

## Зачем

GitHub = Яндекс.Диск для кода, только с историей изменений. Сломал что-то - откатился. Без GitHub любая ошибка Qwen может убить проект.

Три термина, которые нужно знать:
- **Репозиторий** - папка проекта в облаке
- **Коммит** - сохранение изменений (как Ctrl+S для всего проекта)
- **Пуш** - отправка коммитов в облако

## Регистрация (если нет аккаунта)

- Зайди на [github.com](https://github.com) и создай аккаунт
- Запомни логин и пароль
- Желательно настроить 2FA (в Settings → Password and authentication)

## Промпт

```prompt
Подключи этот проект к GitHub.

1. Если у меня ещё нет репозитория - создай ПРИВАТНЫЙ репозиторий на GitHub. Назови по имени моего проекта.
2. Сделай первый коммит со всем кодом проекта (с учётом .gitignore - не коммить .env, .business/, node_modules).
3. Запуши в GitHub.
4. Покажи мне ссылку на репозиторий.

Если нужна авторизация GitHub - объясни пошагово что нажать.
```

## Проверка

Открой ссылку на репо в браузере. Видишь свои файлы? Код в безопасности.

## Попробуй откат (необязательно, но полезно)

Хочешь убедиться что откат работает?

```prompt
Удали главную страницу проекта.
```

Он удалит. Потом:

```prompt
Откати последние изменения. Верни всё как было.
```

Восстановил? Вот и вся магия GitHub. Теперь ты в безопасности - экспериментируй смело.

## Что НЕ коммитить никогда

Проверь `.gitignore`, там должно быть:
- `.env` и `.env.local`
- `.business/` (бизнес-контекст - это приватно)
- `.qwen/settings.local.json`
- `node_modules/`
- API-ключи в коде (ключи только в `.env`)

# Критика плана через 3 параллельных субагента

**Когда брать:** когда Qwen написал первый вариант плана в `plans/YYYY-MM-DD-название.md` и ты готов проверить его прежде чем начинать реализацию.
**Что делает:** запускает 3 субагента параллельно - каждый смотрит на план со своей стороны (техника, бизнес, UX). Возвращает общий отчёт с правками.
**Результат:** улучшенный план с закрытыми дырами, которые ты бы не увидел один.

## Почему это работает

Один агент в одном чате не может «посмотреть на свою работу со стороны». Новый чат + параллельные субагенты - это и есть «взгляд со стороны», который ловит 80% проблем **до того** как ты начал кодить.

## Рабочий цикл

1. Qwen пишет первичный план в `plans/YYYY-MM-DD-название.md`
2. Ты **копируешь ссылку на файл**, открываешь **новый чат**
3. В новом чате запускаешь промпт ниже
4. Возвращаешься к исходному плану и обновляешь с учётом критики
5. **Только после этого** - реализация

## Промпт

```prompt
У меня есть первичный план реализации: [путь к файлу, например plans/2026-04-23-payment-form.md].

Задача:
1. Прочитай план целиком.
2. Прочитай .business/INDEX.md и связанные файлы - чтобы понять контекст проекта.
3. Запусти 3 параллельных субагента на глубокое исследование:
   - агент 1: проверь техническую реализуемость каждой фазы, найди риски и подводные камни
   - агент 2: проверь соответствие плана бизнес-целям из .business/, найди пробелы и противоречия
   - агент 3: сделай ревью UX/пользовательского сценария - где пользователь может застрять, что непонятно
4. Собери их выводы в один отчёт с конкретными правками: что добавить, что убрать, что переформулировать.
5. Покажи мне отчёт. Я решу какие правки принять, и попрошу тебя обновить файл плана.

Всегда отвечай на русском.
```

## Что делать с отчётом

- **Критика обоснована** → обнови план
- **Критика промах** (агент не понял контекст) → отметь себе, пропусти
- **Критика поднимает новый вопрос** → не фикси сейчас, добавь в «Открытые вопросы» плана

## Правило

Не делай все правки разом. Пройдись по отчёту пункт за пунктом. На каждую правку принимай осознанное решение «да/нет/позже».


# «10 причин обосраться» - стресс-тест перед важным шагом

**Когда брать:** перед любым крупным шагом - эфир, деплой, запуск продаж, презентация инвесторам, важное решение.
**Что делает:** находит 10 дыр, которые ты сам не увидишь, потому что слишком близко к задаче.
**Результат:** список конкретных правок в нужных файлах, чтобы этих причин не было.

## Когда применять

- Перед деплоем на прод
- Перед важным эфиром / демо
- Перед запуском продаж
- Перед переносом проекта с MVP на рабочую версию
- Перед большим решением (смена стека, смена аудитории, смена цены)
- Перед релизом фичи

Принцип: любой крупный шаг проходит через этот стресс-тест **до** того как сделан.

## Промпт

```prompt
Сейчас у меня есть [что именно: QWEN.md и .business/, лендинг проекта, план запуска, оффер на продажу - заполни конкретно].

Завтра я буду [что делать: запускать продажи / деплоить на прод / проводить демо для инвесторов - заполни].

Твоя задача - стресс-тест. Найди 10 причин, из-за которых мы обосрёмся:

- где в [главном артефакте] двусмысленности, которые ты как агент можешь понять неправильно
- где в .business/ пробелы, из-за которых решения придётся выдумывать
- где бизнес-логика противоречит сама себе
- где стек или принципы противоречат реальности моей идеи
- где я переоцениваю объём (типа «соберём маркетплейс за день»)
- где риски заложены, но митигации нет
- где пользователь может застрять и уйти
- где может упасть прод
- где я не подумал про безопасность / приватность
- где не продуман следующий шаг после запуска

Не стесняйся. Критикуй жёстко. Я хочу найти эти 10 причин сейчас, а не в проде.

В конце дай список конкретных правок: что и в каком файле исправить, чтобы этих причин не было.
```

## Что делать с результатом

- **Прими правки**, которые согласуешь - попроси Qwen внести их в нужные файлы.
- **Запиши** в `retrospectives/YYYY-MM-DD_HH-MM_stress-test.md` что нашли и что решили.
- **Через день** - перечитай ещё раз. Что-то успеешь закрыть, что-то останется в бэклоге.

## Правило

Этот промпт применяй к **любому большому тексту**: план фичи, оффер на лендинге, структура воронки, схема деплоя. Экономит часы в проде.


# Импорт существующего проекта в `.business/`

**Когда брать:** у тебя **уже есть** рабочий проект (сайт / SaaS / приложение) и ты хочешь навести в нём порядок по методологии второго мозга.
**Что делает:** Qwen читает твой текущий код, структуру папок, README, документацию и сам заполняет `.business/` на основе того что нашёл.
**Результат:** `.business/` под твой существующий проект без ручного интервью.

## Когда использовать vs интервью

- **Используй этот промпт**, если у тебя уже есть код, и Qwen может по нему понять что за продукт, кто аудитория, какая модель монетизации.
- **Используй интервью** (`prompts/setup/04-business-interview.md`), если проект на стадии идеи или у тебя есть только общее представление.

## Промпт

```prompt
У меня уже есть рабочий проект. Код лежит в корне этого репо (или по пути: [ВСТАВЬ ПУТЬ если другой]).

Задача: на основе существующего кода, документации, README, package.json, структуры папок - заполни папку .business/ по методологии второго мозга.

ДЕЙСТВУЙ ПО ШАГАМ:

1. Изучи проект. Прочитай:
   - README.md (если есть) - обычно там основная информация
   - package.json - видно стек, зависимости, название
   - Структура папок - видно архитектуру
   - Код главных страниц (index, лендинг, главная) - видно offer и аудиторию
   - Модели данных (Prisma schema, DB migrations) - видно бизнес-сущности
   - Файлы документации (docs/, .md файлы) - если есть

2. Составь предварительную картину проекта: что делает, для кого, какая модель монетизации (по коду видно есть ли платежи, подписки, тарифы).

3. Задай мне 5-7 вопросов, чтобы закрыть пробелы. ПО ОДНОМУ за раз. К каждому предлагай 3-4 варианта ответа на основе того что ты увидел в коде.

4. После ответов заполни файлы в .business/:
   - company/about.md, company/values.md, company/legal.md
   - products/overview.md, products/pricing.md (если видел цены в коде)
   - audience/avatar.md, audience/segments.md (по тому какие сегменты видны в коде)
   - goals/ - спроси у меня
   - economics/ - если видел данные о ценах/подписках - заполни, остальное спроси
   - marketing/ - channels.md, competitors.md, content.md - спроси
   - assets/brand-guidelines.md - если есть файлы стилей (CSS, tailwind config) - вытащи цвета/шрифты оттуда

5. В конце обнови INDEX.md с оглавлением всей папки .business/.

6. Сделай Reality Check: найди 2-3 пробела в моём проекте (что в коде выглядит незавершённым, противоречивым, или без явной бизнес-причины).

Отвечай на русском. По одному вопросу, не допрос.
```

## После импорта

- Проверь файлы `.business/` - что-то Qwen угадал, что-то нет. Поправь.
- Добавь то, что в коде не отражено (цели на год, приватные конкуренты, прогноз).
- Убедись что `.business/` в `.gitignore` - теперь это приватные данные.


# Планирование недели

**Когда брать:** в начале недели (понедельник утро) или в конце предыдущей недели (воскресенье вечер).
**Что делает:** Qwen читает твои месячные цели, предлагает задачи на неделю, создаёт файл недели в `.business/execution/`.
**Результат:** `.business/execution/YYYY-WNN.md` с задачами по дням и 3-5 ключевыми результатами.

## Принцип

Цели на год → квартал → месяц → **неделя** → день. Неделя = последнее звено между стратегией и реальными действиями. Без недельного плана месячные цели - просто желания.

## Промпт: спланировать неделю

```prompt
Давай спланируем эту неделю.

1. Прочитай .business/goals/monthly.md - фокус месяца.
2. Прочитай .business/goals/quarterly.md - цели квартала.
3. Прочитай .business/execution/backlog.md если есть - что там накопилось.
4. Предложи мне 3-5 ключевых результатов на эту неделю, которые двигают проект к месячным целям.
5. По каждому результату предложи задачи с распределением по дням недели (пн-пт, вых опционально).
6. Создай файл .business/execution/YYYY-WNN.md (используй текущую ISO-неделю) по этому формату:

```
# Неделя YYYY-WNN (DD.MM - DD.MM)

## Фокус недели
[одно предложение: что главное]

## Ключевые результаты
1. [результат 1]
2. [результат 2]
3. [результат 3]

## План по дням

### Понедельник
- [ ] задача

### Вторник
- [ ] задача

...

## Итог недели
[заполняется в воскресенье]
- Что сделано:
- Что не сделано и почему:
- Что перенесено:
- Уроки:
```

7. Покажи финальный файл. Спроси, что поправить.
```

## Промпт: добавить задачу

```prompt
Добавь задачу: [описание задачи].
```

Qwen сам определит куда положить:
- **На конкретный день** - в файл текущей недели в нужный день
- **Без даты / на будущее** - в `.business/execution/backlog.md`

## Промпт: итоги недели

В воскресенье вечером:

```prompt
Закроем неделю. Заполни секцию «Итог недели» в .business/execution/YYYY-WNN.md:
1. Что сделано (отметь фактически закрытые задачи).
2. Что не сделано и почему.
3. Что перенести на следующую неделю.
4. Уроки - что я понял за эту неделю.

Затем предложи перенос несделанных задач: какие в следующую неделю, какие в бэклог.
```

## Правила

- **Не больше 5 ключевых результатов.** Шесть = ноль.
- **Задачи = конкретные действия.** Не «поработать над контенттом», а «написать 3 поста для Telegram-канала».
- **Петля:** месячные цели → неделя → дни → итоги недели → коррекция месячных целей.

## Триггеры (Qwen знает их из QWEN.md)

| Ты говоришь | Qwen делает |
|---|---|
| «давай спланируем неделю» | промпт выше |
| «добавь задачу» | в текущую неделю или бэклог |
| «что на этой неделе?» | покажет файл недели |
| «итоги недели» | заполнит «Итог недели» |
| «перенеси X на следующую» | уберёт из текущей, добавит в следующую |
